# 의사결정 기록 (DECISIONS)

백엔드 연동 과정에서 확인 없이 스스로 판단한 사항과 근거를 정리한다.

## 아키텍처

### 1. Vite SPA → Next.js(App Router) 마이그레이션
명세는 Server Actions, 미들웨어, RSC, Vercel Cron, `/tasks/[id]` 딥링크를 전제하지만, 인수받은 산출물은 Vite + React SPA 였다. Vite 에서는 이 요구를 구현할 수 없어 Next.js(App Router)로 마이그레이션했다. 기존 JSX/Tailwind 마크업은 보존하고 라우트 분리와 서버/클라이언트 분리만 수행했다. (사용자 확인을 받은 유일한 지점)

### 2. Next.js 14 + React 18 채택
기존 `peerDependencies` 가 React 18.3.1 이라 호환성을 위해 Next 14(App Router, Server Actions 안정판)를 선택했다. Next 14.2.x 는 보안 패치 버전(14.2.35)으로 고정했다.

### 3. `src/` 디렉터리 + `@/*` alias 유지
기존 코드가 `src/` 기준이므로 `src/app` 구조를 유지했다. 명세의 `lib/db/...`, `types/index.ts`, `lib/notifications/` 는 각각 `src/lib/db/...`, `src/types/index.ts`, `src/lib/notifications/` 로 해석했다. `supabase/` 와 `middleware.ts` 는 루트에 둔다.

### 4. 미사용 의존성/컴포넌트 제거
Figma 템플릿이 포함한 다수의 미사용 라이브러리(MUI, recharts, react-dnd, embla, sonner, 다수 radix 등)와 화면에서 쓰이지 않는 shadcn `ui/` 컴포넌트를 제거했다. 실제 화면은 lucide 아이콘 + 순수 마크업만 사용한다.

## 데이터/타입

### 5. `changed_by` 는 이름으로 매핑
DB `task_history.changed_by` 는 uuid 지만 기존 화면은 사람 이름 문자열을 렌더한다. 마크업 보존을 위해 조회 계층에서 uuid → 이름으로 변환해 `TaskHistory.changedBy` 에 이름을 담는다.

### 6. `Template.itemCount` 는 파생 값
정본 타입에는 없지만 `/templates` 화면이 사용한다. DB 컬럼이 아니라 `template_items` 개수에서 매퍼가 계산한다. (HANDOFF_REPORT 4-1 참조)

### 7. DB 타입은 수동 정의
`any` 금지 원칙에 따라 `src/lib/db/database.types.ts` 를 스키마와 1:1로 수동 작성했다. 로컬 Supabase 연결 후 `pnpm gen:types` 로 자동 생성본으로 교체 가능하다.

## 권한/인증

### 8. 사전 등록 이메일만 로그인
매직 링크는 `signInWithOtp({ shouldCreateUser: false })` 로 발송해 auth.users 에 존재하는(사전 등록된) 이메일만 링크를 받는다. `getCurrentUser` 는 추가로 `public.users` 프로필 존재를 확인한다.

### 9. 항목 수정 버튼은 관리자에게만 노출
명세에 항목 수정 권한 주체가 명시되지 않아, 생성과 동일하게 관리자 전용으로 판단했다. 서버(액션 + RLS)에서 강제하고 UI 버튼도 관리자에게만 노출한다.

### 10. 담당자 tasks 컬럼 제한은 서버 액션이 담당
RLS 는 행 단위라 담당자가 자신의 task 행을 update 하는 것까지만 통제한다. 담당자가 상태 외 필드를 바꾸지 못하도록 하는 컬럼 단위 제한은 서버 액션(담당자는 상태 전환만 허용)이 담당한다.

## 알림

### 11. 웹훅은 단일 채널, 수신자는 메시지 본문으로 구분
웹훅이 단방향·단일 채널이라 사용자별 라우팅이 불가능하므로, 메시지 본문에 담당자 이름을 넣어 구분한다.

### 12. dedupe 는 다이제스트 단위
크론 다이제스트는 담당자당 한 건으로 합쳐 보내므로 dedupe_key 를 `digest:{user_id}:{date}`, 관리자 마감초과 통지는 `overdue_admin:{date}` 로 구성했다(명세의 `due_soon:{task_id}:{date}` 형식을 다이제스트 단위로 일반화). 즉시 발송 알림은 dedupe 대상이 아니라 로그를 남기지 않는다.

### 13. 알림 실패는 액션을 실패시키지 않음
웹훅 전송 실패가 사용자 액션 전체를 막지 않도록 전송을 try/catch 로 감싸 콘솔에 기록한다. 입력 검증 실패는 기존 UI 오류 표시로 사용자에게 명확히 알린다.

## 스토리지

### 14. 스크린샷 표시 위치 추가
기존 화면은 스크린샷을 저장/표시하지 않았다. `Task.screenshotUrl` 이 타입/DB 에 존재하므로, 완료 요청 시 파일 업로드(비공개 버킷) 후 상세 화면에 서명 URL 링크("스크린샷 보기")를 기존 톤으로 추가했다.

## 사용자 요청 반영 (초기 명세 이후)

### 15. 로그인 우회 토글
`NEXT_PUBLIC_AUTH_BYPASS=1` 이면 매직 링크 로그인을 건너뛰고 시드 관리자로 접근한다. 로그인 코드(매직 링크/콜백/미들웨어 세션 갱신)는 그대로 두고, 검사 지점만 우회한다. 우회 시 조회/쓰기는 RLS 를 넘기는 서비스 롤 클라이언트를 사용한다. 로그인 복구는 이 env 를 지우거나 0 으로 두면 된다.

### 16. 웹훅 URL 은 화면 입력값만 사용, 폴백 없음
웹훅 URL 이 자주 바뀌어 사용자(관리자)가 화면에서 입력하도록 했다. `app_settings` 테이블에 저장하고 관리자 보드 상단에서 편집한다. 값이 없으면 알림을 발송하지 않는다(환경 변수/콘솔 폴백 제거).

### 17. 일정(출시 국면)으로 마감일 도출
출시 국면(예: 사전알림, 언팩, 사전예약, 사전개통, 출시)을 `schedule_phases` 에 저장하고 관리자 보드의 "일정" 팝업에서 전체 교체 방식으로 편집한다. 항목 생성/수정 시 국면을 고르면 그 **시작일**이 마감일로 자동 입력된다(직접 수정 가능). 단순함을 위해 항목에 국면 링크는 저장하지 않고 마감일만 저장하므로, 일정 편집이 기존 항목의 마감일을 바꾸지 않는다. 마감 초과/임박/크론 로직은 기존 `dueDate` 를 그대로 사용한다.

## 재설계 (Phase A: 로그인 제거 + 상태 단순화)

### 18. 로그인 완전 제거 + 단일 운영자 프로필
진입 즉시 대시보드를 보여주기 위해 로그인(매직 링크/콜백/미들웨어 보호)을 제거했다. `users` 의 고정 id 행 하나(`PROFILE_USER_ID`)를 "현재 사용자"로 사용하며, 이름/이메일은 좌측 내비의 "프로필 수정"에서 바꾼다. 이 프로필 id 가 항목 이력(`changed_by`)·코멘트(`author_id`) 작성자로 기록된다. 마이그레이션 0005 에서 `users` 의 `auth.users` FK 를 끊고 id 기본값을 부여해 로그인 없이 프로필을 관리한다. 세션이 없으므로 모든 DB 접근은 서비스 롤(RLS 우회)로 이뤄진다 → `SUPABASE_SERVICE_ROLE_KEY` 가 필수다. (역할 기반 권한/`AUTH_BYPASS` 토글은 제거)

### 19. 상태 3개로 축소 (할 일 / 완료 / 반려)
상태가 많아 보기 어렵다는 피드백에 따라 화면 상태를 3개로 줄였다. `in_progress`·`review_requested`(완료요청/승인 플로우)는 제거하고, 기존 데이터는 마이그레이션 0005 에서 '할 일'로 이관한다. enum 값 자체는 과거 이력 표시를 위해 남겨둔다. 라우트는 루트 `/` 를 보드로 통합했다(담당자/관리자 화면 분리 제거).

### 20. 드래그 앤 드롭 칸반 (Phase B)
상세 페이지에 들어가지 않고 보드에서 바로 상태를 바꾸도록 HTML5 드래그 앤 드롭을 붙였다. 노션식으로 어느 컬럼으로든 옮길 수 있게 전이 규칙을 "자기 자신 외 모든 상태로 이동 허용"으로 넓혔고, 반려로 옮길 때만 사유 입력 모달을 띄운다. (초기 명세의 "드래그 칸반 금지"는 사용자 요청으로 뒤집음)

### 23. 담당자 인라인 변경 · 항목별 수동 알림(Teams @멘션) · 카드 상태 버튼 (Phase E)
- **담당자 인라인 변경**: 대시보드 카드에서 담당자 select 로 바로 변경(`changeTaskAssignee`). 상세 진입 불필요.
- **항목별 수동 알림(호출)**: 배치가 아니라 사용자가 카드/상세의 버튼으로 직접 호출(`notifyTaskNow`). 담당자에게 알림을 보낸다.
- **MS Teams @멘션**: 순수 텍스트 웹훅은 태그가 불가능하므로, 멘션 대상이 있으면 Adaptive Card + `msteams.entities` 페이로드로 전송한다(`transport.ts`). 멘션 id 는 담당자의 조직 이메일(UPN)을 사용하므로, users 이메일을 실제 Teams 계정 이메일로 넣어야 태그가 걸린다. 웹훅은 Adaptive Card 를 받을 수 있는 Teams 용(Workflows 또는 Incoming Webhook)이어야 한다. 웹훅 미설정 시 호출 버튼은 안내 메시지를 반환한다.
- **카드 상태 버튼**: 카드에 `allowedNextStatuses` 기반 완료/반려/할 일 버튼을 직접 노출. 상세 진입 없이 밖에서 상태 변경(반려는 사유 모달). 보관된 회차는 읽기 전용.
- **멤버(담당자) 관리**: 로그인이 없어 담당자 목록/이메일을 화면에서 직접 관리해야 한다. 좌측 내비 '멤버 관리'에서 추가/수정/삭제(`createMember`/`updateMember`/`deleteMember`). 이메일은 @멘션 id 로 쓰이므로 실제 조직 이메일을 넣는다. 운영자 프로필은 삭제 불가, 항목/이력에 연결된 멤버는 FK 로 삭제가 막힌다.

### 22. 템플릿 생성·수정·삭제 (Phase D)
예판마다 반복되는 세팅 묶음을 관리하도록 템플릿 CRUD 를 추가했다. `/templates` 에서 새 템플릿/수정/삭제하며, 편집 모달은 이름·설명과 항목 목록(제목·담당자·환경·차단·컨플루언스/확인 URL·확인 포인트)을 다룬다. 항목은 전체 교체 방식으로 저장한다(수정 시 delete 후 insert). 스키마 변경은 없다(기존 `templates`/`template_items` 사용). 담당자 미지정 항목은 저장을 막아 템플릿 생성 시 담당자 누락 오류를 예방한다.

### 21. 프로젝트(회차) 단위 대시보드 + 보관 + 메모 패널 (Phase C)
예판 회차마다 대시보드를 새로 열고 완료된 회차는 보관하는 요구에 맞춰 `projects` 를 도입했다(0006). `tasks.project_id` 로 회차에 소속시키고, 보드는 `/?project=<id>` 로 한 회차만 보여준다(기본은 최신 활성 회차). "새 대시보드"는 현재 회차를 보관(선택)하고 새 회차를 열어 그리로 이동한다. 보관된 회차는 읽기 전용(생성·드래그·메모 편집 불가)이며 드롭다운으로 언제든 다시 열람한다. 오른쪽 "메모/이슈 로그" 패널(`project_notes`)은 사업이 공유 안 해준 맥락(예: 36개월 할부 결제 오류)을 회차 단위로 기록한다. 템플릿 생성은 현재 활성 회차를 대상으로 한다. (초기 명세의 "다중 프로젝트 금지"는 사용자 요청으로 뒤집음)
